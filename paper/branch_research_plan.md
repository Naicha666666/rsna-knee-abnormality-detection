### B2　膝别推断与展开式空间归因（P1，Kaggle CPU 核 + 离线，不占 R9700、不占提交）

**问题**
1. 能否从 DICOM 几何为接近 100% 的 study 推断出膝别（左 / 右）？目前只有 52% 的序列带 `Laterality` 标签。
2. 知道膝别之后，阳性时注意力是否移向解剖上预期的那一侧？

**依据**
- S7 只能用与膝别无关的"折叠深度"，所以分不出外侧端和内侧端，ACL 落在矢状一端也无法解释。
- 机制性先验：ACL 撕裂常伴随**外侧**股骨髁和胫骨后外侧的骨挫伤（轴移损伤的典型模式），所以 ACL 阳性时注意力应移向外侧端。这个预测可以被证伪。

**预注册的方向性预测**（矢状展开深度上，阳性 − 阴性的注意力质量）：
- ACL → 外侧端
- Medial Meniscus、Medial OA、MCL → 内侧端
- Lateral Meniscus、Lateral OA → 外侧端
- PF OA → 中央（S7 已见）

判定规则沿用 S7：分层 study bootstrap；只有 C6r 和 C10 都复现、且符号符合预测，才算支持。

**执行步骤**
1. **头信息核**（由 `rsna-knee-sag-geometry` 派生，覆盖全部 4407 个训练 study）。每个 study 记录：
   - 矢状两个序列的 `Laterality`、`BodyPartExamined`、`SeriesDescription`、IOP；
   - 排序后首尾两片的 IPP x；
   - 全部切片 x 的中位数（≈ 膝关节中心 x）；
   - 冠状、轴位各一个头：IOP 行向量的 x 分量，决定图像左右与患者左右的对应关系。

   预计 1–1.5 h（只读文件头）。
2. **膝别规则**：DICOM 患者坐标系（LPS）里 +x 指向患者左侧，所以膝关节中心 x < 0 → 右膝，x > 0 → 左膝。这个规则**是一个待验证的假设**：它依赖膝关节扫描通常偏离等中心。
   - 用带 `Laterality` 标签的约 52% 序列验证。**预注册的采用门槛：一致率 ≥ 95%，并报告 |x| 太小、判不出的比例。**
   - 达不到门槛时的退路：只用带标签的子集；或者从图像判断（腓骨头总在外侧），但后者工作量大。
3. **方向**：每个矢状序列的语料行号沿患者 x 的方向 = sign(x_末片 − x_首片)。结合膝别，可以判断"行号增大是不是朝外侧"，从而把深度展开为 0（内侧端）到 1（外侧端）。
4. **展开式 S7**：在 58 金标上，用展开后的深度重跑 `spatial_attribution.py` 的格子分析和两端分析，按上面的方向预测判定。
5. **（可选）图像内侧别归因**：对冠状窗口按膝别统一方向，计算基于梯度的显著性在内侧半边和外侧半边各占多少，检验 Medial OA / MM 阳性是否偏向内侧半边。在 3070 上只需几分钟。
6. **侧别混淆诊断**：在金标里，取只在一侧阳性的病例（例如 MM+ 且 LM−，或者反过来），计算 score(MM) − score(LM) 区分两类病例的 AUC；OA 同理。只做描述，用来判断 B7 值不值得做。

**产出**：`results/laterality_v1.csv`（膝别、方向、来源、与标签的一致率）、`results/spatial_unfolded_v1.csv`、补图 `s7c`。
**成本**：1 个 Kaggle CPU 核，离线分析约 2–3 h。
**风险**：膝关节若居中扫描，x 偏移接近 0，就判不出膝别；分侧标签阳性少（MCL 9、Lateral OA 11、Medial OA 15、LM 23、MM 26），功效低。
**后续**：膝别准确，且第 6 步显示侧别混淆 → 进入 B7。

### B3　验证失效图谱：C11 / C8 / C9b 单独上公榜（P1，只需提交，不训练）

**问题**：C10 上金标判断失效，是孤例，还是金标对架构 / 池化类改动的系统性盲区？

**设计**：三个已训练好的 C 线单模，各单独整版提交一次：

| 模型 | 改动 | 对照 | 金标 |
|---|---|---|---|
| C11 | 平均池化（ConvNeXt-S） | C10（0.912） | 0.889 |
| C8 | RadImageNet ResNet-50 | C6（0.935） | 0.839 |
| C9b | DINOv2 ViT-B + 逐层学习率衰减 | C6（0.935） | 0.894 |

C11 − C10 第一次给出**池化在隐藏集上的效应**，补上未归因清单的第 2 条。

**预注册**：提交前，先用已有的金标逐例预测算出每对的金标 Δ 和配对 bootstrap 95% 区间（C11 / C10、C8 / C6、C9b / C6；C9b 的预测在 R9700 的 `gold_fuse_check_c9b.npz` 里）。判定：公榜 Δ 落在金标区间外 → 金标失效；落在区间内 → 金标只是功效不足，并不矛盾。

**执行步骤**
1. 上传 C11 权重（`local_c11_.../corpus0_topk_avg.pt`），新建数据集 `rsna-knee-c11-weights`。C8、C9b 用已有的 `rsna-knee-c8-weights`、`rsna-knee-c9-weights`（后者的内容已确认是 C9b）。
2. 写 `scratchpad/s2_extension_predictions.py`，输出 3 对的金标区间并写入 LOG（预注册）。
3. 由 `rsna-knee-c10-solo` 派生 3 个整版单模核，改 ckpt、数据集，以及 arch 由 checkpoint 决定。
   - **C11 的特殊风险（已核实）**：C11 的 checkpoint **没有记录池化方式**，元数据里只有 arch / res / slots / weights。直接推理会静默地按注意力池化跑。核里必须在加载前设置 `RAPTOR_POOL = "mean"`，并在日志里断言。另外，在 R9700 上先用同一推理路径复现 C11 的金标 0.889，再推送。
   - C9b 的 ViT-B 在推理时按 checkpoint 的 arch 随机初始化，再严格加载（C10 已验证过这种做法）；它在 C6 + C9b 融合核里也跑通过。
4. 跑可见集自检后，提交 3 次（可以放在同一天）。
5. 扩展 S2 的表和主图 3，把 3 个新点加上；补登私榜条目 H7。

**产出**：Paper B 的核心图，即金标 vs 公榜，覆盖 4 种骨干和 1 种池化。
**成本**：3 次提交，准备约 2 h，Kaggle 端约 3–4 h。

### B4　两个头号结论的重训复现（P2）

**问题**：专科化 +0.024 和换骨干 −0.021 都是单种子。换一个种子还成立吗？这也是论文里每条结论都绕不开的"重训噪声"问题。

**设计**：种子 43，其余逐项相同。
- PF-v1（种子 43）→ PF 单列探测
- C10（种子 43）→ 整版单模提交，再加一个 PF 单列探测

**预注册**
- **换骨干复现**：LB(C10 s43) ≤ 0.928 → 复现"明显有害"；落在 0.929–0.937 → 原来的 −0.021 有一部分是种子运气。
- **专科化复现**：PF(PF-v1 s43) − PF(C10 s43) ≥ +0.024 → 复现；只差 +0.012 → 边缘；≤ 0 → 不复现，链 E 降级为"单种子观察"。
- **首次测量 ConvNeXt 线的重训噪声**（描述性）：|LB(C10 s43) − 0.912|、|PF(PF-v1 s43) − 0.884|、|PF(C10 s43) − 0.860|。

**执行步骤**
1. 给 `train_pf1_local.py`、`train_c10_local.py` 加环境变量 `RSNA_SEED`（默认 42，旧行为不变），输出目录加后缀 `_s43`。冒烟一次。
2. R9700 依次训练两个模型，约 2 × 3.2 h。
3. 补算金标预测（只作辅助），上传权重。
4. 探测核：PF-v1 s43 用 pf1-probe 模板；C10 s43 用 c10-solo 和 c10-pf-probe 模板。
5. 补登私榜 H8 → 提交 3 次 → 判定，写入 findings（§18 和 §17 的复现说明）。

**成本**：R9700 约 6.5 h，3 次提交。
**意义**：决定论文里"专科化有效"和"换骨干有害"能写多硬。

### B5　软标签吸收阈值错位的因果检验：二值化对照（P2）

**问题**：S6 观察到，阈值错位的标签（Effusion、Contusion）报告噪声很大，但影像模型仍然很强。我们推测这是因为软标签按严重度保留了序数信息。把标签二值化，能否让这两个标签**选择性地**变差？

**设计**：C6r 配置（CoAtNet、12 标签、软目标 = 正则 + 4 LLM 的均值），只改一处：目标在 0.5 处二值化，y = 1[p ≥ 0.5]。记为 C6b。对照是现有的 C6r 权重，按惯例不重训。

**预注册**（两组合并探测，每个模型各 2 次）：
- 探测 A = Effusion + Contusion（k = 2，平均值 1 单位 = 0.006）；
- 探测 B = ACL、MCL、Medial Meniscus、Baker's（k = 4，1 单位 = 0.003）。这 4 个都是"信息充分、可抽取"的对照标签。
- **机制得到支持的条件**：Δ_A = A(C6b) − A(C6r) ≤ −0.012（2 单位），**同时** |Δ_B| ≤ 0.003（≤ 1 单位）。
- 其他读法：两者都降 → 二值化整体有害，不能说是"选择性"；两者都不变 → 软标签的这个作用没有被证实。
- Synovitis（漏报型）预测不变，可选 1 个单列探测作描述。

**执行步骤**
1. `src/dataset.py` 加开关 `CORPUS_BINARIZE_TARGETS`（默认 False）：在报告源平均之后、金标覆盖之前做阈值化；只作用于训练目标。
2. 由 `train_c6r_local.py` 派生 `train_c6b_local.py`，冒烟一次（打印二值化后各标签的阳性率，与软目标做对比）。
3. R9700 训练约 3.5–4 h；金标评估作辅助（Effusion 有 35 个阳性）。
4. 确认 `rsna-knee-c6r-weights` 仍在；上传 C6b 权重。
5. 4 个合并探测核：后处理改为"保留集合、其余填 0.5"，并断言保留列不是常数。平均值按 (12·LB − (12 − k)·0.5) / k 计算。
6. 补登 H9 → 提交 4 次（可分 2 天）→ 判定。

**成本**：R9700 约 4 h，4 次提交。
**意义**：把 §21 的"阈值错位可被吸收、漏报不行"从相关性观察升级为干预证据，这是机制链里最弱的一环。

### B6　S4 v2：更细的空间建模（条件分支）

**闸门**：只有 B0 判定"顺序有效"（T − K ≥ +0.024）才启动。否则在 findings 里写明"PF 的增益来自专科化，而不是空间顺序"，空间建模这条线就此关闭。

两个选项按成本从低到高：
- **v2a 厚窗口**：每个窗口叠 7 行（c − 3 … c + 3），通过扩宽 stem 输入；在 T 的有序 head 上只改这一个变量。实测成本与 T 相同（274 ms / 步，7.6 GiB）。1 次训练 + 1 次探测。
- **v2b 原分辨率中央带**：重新导出 SagF / SagS 中央 ±25 mm 内的全部原始切片（每个序列约 15 张，层距 3.3 mm；4407 × 30 × 336² ≈ 15 GB）。
  - 步骤：两个 CPU 导出核（分片）→ 用 `stream_kernel_output.py` 分块拉回 → 新的 `open_corpus` 分支和测试端解码函数 → 有序 head 训练 → 探测（隐藏集要现场解码，先估算运行时间）。
  - 成本高，只在 v2a 也是正结果时才考虑。

每个选项各自预注册，判据仍用单列 2 单位。

### B7　膝别规范化训练（条件分支）

**闸门**（三条同时满足）：

- B2 第 6 步显示侧别混淆（具体门槛在 B2 结果出来前写定）；

**设计**：C6r 配置，加上规范化：

- 矢状两个槽内把行序反转，使行号统一朝外侧增大。

在 `read_windows` 里按 study 的标志即时变换，不需要重新导出语料。测试端在核里用同一条规则从 DICOM 头算膝别；判不出的 study 不翻转，并在日志里计数（fail-closed：比例超过预注册上限就停）。

**成本**：1 次训练（约 4 h）+ 4 次探测（每个模型 2 次）。
**意义**：这是唯一一条有机制依据、可能改善 Lateral OA / LM 的路线。S7 已经说明，"选窗口"这条路对它们走不通。

### B8　其余弱标签的"只训单标签"专科，用合并探测读数（可选，P3）

**问题**：PF-v2 显示"只训 PF OA"有 +0.012 的效应（边缘）。这种标签层面的专科化，对其他弱标签也成立吗？之前放弃 S1 的原因之一是单列分辨率不够，合并探测能解决这个问题。

**设计**：沿用 PF-v2 的配方（只训单标签、全部窗口、k_eval 42），分别训练 Synovitis、Lateral OA、Lateral Meniscus 三个专科。对照用现有的 C10。

**预注册**：3 列合并探测（Syn、LatOA、LM；平均值 1 单位 = 0.004）。
- 专科三联（一个核跑 3 个 checkpoint，各出自己那一列）的均值 − C10 的同列均值 ≥ +0.008（2 单位）→ 推广成立。

**成本**：R9700 约 10 h（3 × 3.2 h），2 次提交（另有 3 次可选）。
**定位**：可选，需要你另外批准。它和已封存的 S1（Lateral OA 窗口专科）不是一回事：它只改标签，并且用合并探测解决了分辨率问题。

## 4. 不建议做的（封存）

| 方向 | 理由 |
|---|---|
| Lateral OA 窗口专科（S1） | S7 没有可复现的空间信号；内外侧在窗口级看不到。只经由 B7 的路径重开 |

| 用积液推断 Synovitis 等标签工程 | 漏报的信息不在报告里；把它工程化进目标会混入未经验证的临床假设 |
